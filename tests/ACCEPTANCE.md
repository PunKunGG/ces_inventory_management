## Execution evidence

- Windows with Python 3.14.0 and a disposable database per test.
  `.venv/Scripts/python -m unittest discover -s tests -v` passed all
  20 service and HTTP tests in 16.054 seconds. Chrome and ChromeDriver 143.0.7499.169 ran the
  optional `python -m unittest discover -s tests -p browser_smoke.py -v`
  on a temporary loopback-only Flask server, one test passed in 15.490 seconds.
- With 1,006 synthetic inventory items, single local Flask test-client calls
  took 0.122 seconds for a code search and 0.116 seconds for item detail.
- The lead verified the Waitress server and demo CLI setup on loopback and
  independently decoded the SVG QR with ZXing to confirm its exact URL.
- The low report returned only headers before the report-kind filter fix and
  passed its exact alert fixture after the fix. The stale return form regression
  verifies an old form cannot select the new loan implicitly on retry.

## Physical QR checklist

1. Place the Windows demo host and the test phones on the approved test network
   and configure the public-facing demo URL. Use synthetic data.
2. Print the generated QR with its URL. Scan with the native Camera on iPhone and
   Android, first from a browser with no session and then with an active session.
3. Confirm login/logout, dashboard access by role, and receive, issue, loan and
   return on both phones. Record device/OS/browser and network details.
4. Type the printed URL directly and verify the same entrance. Test keyboard
   interaction and field feedback separately.
